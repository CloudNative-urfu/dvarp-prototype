# Мануалы: трейс механик для полигона

Каталог документов-инструкций «как это устроено» в прототипе. Назначение: в полигоне
(будущем соседнем сервисе) планируется авторазметка чужих процессов агентом; агенту
нужны образцы таких документов. Каждая запись — описание механики в стиле инструкции
для агента, с `path:line`-ссылками на актуальный `develop`.

Это общий запас знаний, а не openspec-спецификация: openspec-каталоги описывают
конкретные изменения, мануалы — живые механики, которые переживают изменения.

Терминология: в текстах мануалов (и в каноне до правки dvarp#20) «полигон» может
означать тестовый стенд прототипа; по новому сценарию (2026-11-13) СС = прототип,
полигон = будущий соседний сервис. При чтении опираться на контекст.

## Правило ведения (см. AGENTS.md, «Трейс для полигона»)

- Содержательное изменение механики → добавить/обновить соответствующий мануал
  в том же PR; новая механика → новый документ.
- В шапке каждого мануала — срез кода (ветка/коммит, дата) и пометка об актуальности.
  При переписывании логики мануал актуализируется по новым путям.
- Формат: markdown, русский, `path:line` обязательны.

- Подбор и выбор конфигураций: основания выбора (preregistered-матрица, контроли,

  выделить отдельный мануал при следующей ревизии.

  после #19/#33 (распил на сервисы меняет топологию).
