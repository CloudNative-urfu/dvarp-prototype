## Why

The research canon changed (CloudNative-urfu/dvarp PR #17, section «Отклонения канона» in
`docs/guardrails_requirements.md`; revised queue analytics decisions of 2026-11-13 in
CloudNative-urfu/dvarp#18). The scaffold still implements the factory version: a `g_simple`
structured-form baseline (FR-1.12), a factory config set instead of the research matrix of
`guardrails-research-design.md` §4 (issue #7), attacks with goal `shift` that count an escalation
as a successful attack (FR-1.21), and a discrete-event queue simulation whose `Q(g)` feeds L*
(FR-1.15/1.16) although with N≈24 cases per run it never reaches an informative saturation
regime. Issue #29 brings the prototype to the canon in one change, with a single sanctioned
refreeze (absorbs #7).

## What Changes

- **Configs (one refreeze, `freeze --replace`)**: remove `g_simple` and the frozen package
  `darp_range/simple_baseline/`; the preregistered set becomes the §4 matrix: baselines `g0` +
  `g_proc`; positional matrix — builtin guard at input / context / tool / output and all four
  layered — × three canon reaction policies (`canon_isolate`, `canon_escalate`,
  `canon_terminate`); `g_in_oss` (OSS detector at input, fixed reaction); controls `g0_seed2`
  and `g_in_detect_only`; leave-one-out of `g_layered`. 24 configurations, previous lock kept in
  `configs/history/`.
- **Corpus v2**: drop the goal=`shift` pairs p21–p24 (attack + paired control) and their
  `holdout_v2` paraphrases; remove `shift` from the taxonomy (corpus, attacker goals) and from
  success criteria (evaluator, attack cards). Escalation is a neutral outcome. Regenerated
  `corpus/MANIFEST.json`, derived manifests, `artifacts/attack-cards.json`. Mode D multi-turn
  attacks are verified to be predefined sequences independent of agent replies (FR-1.20).
- **Queue analytics (canon dvarp#18)**: escalation share `E(g)` is the primary queue metric,
  measured in paired runs and split by traffic class (`E_L` legal = natural + FP, `E_A` attack).
  `λ_Q = λ_L·E_L + λ_A·E_A`; M/M/1 at K=1, M/M/c (Erlang C) at K>1; `C_Q` uses the unconditional
  delay per legal client `Q_L = E_L·W_q` and the probabilistic SLA term
  `c_sla·P_sla_L`, `P_sla_L = E_L·P(W_q > Q_SLA)`; conditional `W_q` and `P(W_q > Q_SLA)`
  published alongside; `P_abandon` removed (non-claim: abandonment is not modelled);
  sensitivity grid K×S (4/8/15 min × 1/2 operators) at fixed intensity; ΔQ in L* is the
  analytic estimate; ρ ≥ 1 → status `queue_unstable` (inadmissible at any L_viol). The DES is
  taken out of the measurement path (kept only as a numerical check of the formula).
- **Docs**: `docs/traceability.md` (FR-1.12, FR-1.15/1.16, FR-1.20, FR-1.21, link to the dvarp
  «Отклонения канона» section), `docs/configs.md`, `docs/repo-map.md`, README/AGENTS frozen
  directory lists, `corpus/README.md`.

## Capabilities

### New Capabilities
- `config-matrix`: the preregistered configuration set as the research matrix §4.
- `attack-corpus`: corpus v2 taxonomy without `shift`, escalation as a neutral outcome, FR-1.20
  predefined multi-turn sequences.
- `queue-analytics`: escalation share by traffic class and the analytic queue block in the
  report and in L*.

### Modified Capabilities
- `traceability` (from `polygon-alignment`): rows FR-1.12, FR-1.15/1.16, FR-1.20, FR-1.21 updated
  with the canon deviations.

## Impact

- Frozen defense code changes (`configs`, `guard_policy` presets; `simple_baseline` removed):
  owner-sanctioned refreeze requested in issue #29; `configs.lock.json` regenerated by
  `python3 -m darp_range.configs freeze --replace`.
- Run result format: flows no longer carry a DES `queue` section; pairs no longer carry
  `impact` / `sensitivity` / `pair_error`; metrics `continuity` is rebuilt around `E_L`, `E_A`
  and the analytic block; break-even gains the `sla` term, `C_sla` price range (32 price
  corners instead of 16) and the `queue_unstable` status.
- Dependency: the canon-docs PR for dvarp#18 is not merged yet; the queue part follows the
  decisions written in dvarp#18 and in this issue (they agree).
- Overlap: `origin/refactor/19-svc-decomposition` (issue #19) so far adds only openspec docs;
  its plan names `simple_baseline` among frozen packages and keeps `manual_queue` on the
  orchestrator side — both change here; its future `runner/flow.py` seams will meet the flow
  changes of this change.
