# Why

Issue #61: `no_network()` запрещал любые TCP/UDP-соединения, включая 127.0.0.1, поэтому
собственные сервисы не могли работать внутри офлайн-контура, а расчёт метрик уходил
в процесс (defer-схема #56: сервис звался после блока запрета). Решение тимлида
(2026-11-18, PR #69 отклонён): СС не считает сырьё — движок метрик единственный
расчётчик; расчёт — только через metrics-svc; запрет сети ослабляется allowlist'ом
собственных сервисов, каждое разрешённое соединение фиксируется в contour.json.

# What Changes

- `contour.no_network(allow=...)`: пропускает соединения только к собственным сервисам
  по allowlist `имя → порт` (порт — из ready.json сервиса), только loopback; каждый
  разрешённый ход фиксируется (`guard.allowed`, в contour.json — сводно); всё остальное
  — по-прежнему `NetworkBlocked`.
- `run_offline`: metrics-svc стартует до блока запрета сети, прогон и расчёт — внутри
  блока по allowlist; расчёт в процессе (`metrics_svc=False`) отклоняется.
- `run_live`: расчёт метрик — также только через metrics-svc (`--no-metrics-svc`
  отклоняется).
- CLI `--metrics-svc` — по умолчанию включён (BooleanOptionalAction).
- Спека capability `metrics-service`: расчёт контуров только через сервис + сценарий
  allowlist; мануал `metrics-svc.md` — раздел про allowlist; `run-lifecycle.md` — схема.

# Capabilities

### Modified Capabilities
- `metrics-service`: расчёт метрик контуров offline/live выполняется только сервисом;
  запрет сети пропускает только loopback-соединения к собственным сервисам.

# Impact

Канон не меняется (dvarp#20 п.2 остаётся истиной). Формулы и парити движка не меняются
(байт-в-байт тесты #56 остаются). Независимый пересчёт в процессе остаётся шагом
verify/acceptance — это проверка движка, а не расчёт контура.
