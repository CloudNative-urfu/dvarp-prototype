# Design

## Allowlist в `no_network()`

`no_network(allow)` принимает отображение `имя сервиса → порт`. Правило пропуска:

1. AF_UNIX — разрешён как прежде;
2. TCP/UDP-цель — `(host, port)`; порт есть в allowlist **и** host — loopback
   (`127.0.0.1`, `::1`, `localhost`, `.localhost`) → соединение выполняется, ход
   фиксируется в `guard.allowed` ({service, host, port} на каждое соединение);
3. всё остальное (не loopback, порт вне allowlist, неразбираемая цель) —
   `NetworkBlocked` + запись в `attempts`, как прежде.

`to_json()` агрегирует разрешённые ходы по (service, host, port) с числом соединений —
это и попадает в `contour.json`. Полный список ходов живёт в объекте guard (для тестов).
Смысл: наружу — по-прежнему ничего; разрешено только то, что сам контур и поднял.

## Офлайн-конвейер

Порядок в `run_offline`:

1. `_prepare` (конфигурации, каталог);
2. `MetricsService` стартует **до** блока запрета (его ready.json даёт порт);
3. `no_network(allow={"metrics-svc": port})` — под ним: прогоны всех seed и расчёт
   метрик каждого seed через сервис (смоук прибора → `compute`);
4. `contour.json` собирает guard после блока.

Расчёт в процессе для контуров отклоняется (`metrics_svc=False` → `PipelineError`):
движок — единственный расчётчик (dvarp#20 п.2, решение по #61). Независимый пересчёт
в процессе остаётся только в verify/acceptance как **проверка движка** — это не расчёт
контура. Живой конвейер (`run_live`) — тот же принцип: расчёт только через сервис.

Порт сервиса не определился (None) — allowlist пуст: соединения запрещены целиком
(fail-closed, расчёт не пройдёт).

## Совместимость

Формулы, отчёт и парити движка не меняются (байт-в-байт тесты #56). `--metrics-svc`
по умолчанию включён; `--no-metrics-svc` отклоняется с объяснением. Мутационная
проверка контура обновлена под новую форму блока запрета.
