## Context

Состояние после rev9 (подтверждено критиком): bwrap-sandbox атакующего, IPC JSON-lines по закрытой
схеме (`isolation/ipc.py`), брокер `SandboxedAttacker` (`isolation/sandbox.py`).

Слабые места:
- `record_from_json` строит `AttemptRecord` из полей ребёнка;
- `_pump` передаёт `event` в `writer.emit`, и тот бросает `EventLogError` вне `IPCProtocolError`;
- пробы `run_probes` выполняются staged-пакетом атакующего;
- `Runner(attacker_factory=None)` идёт in-process (`runner/flow.py:407`), а `build_manifest` не знает `claim_level`.

`verify_e2e.py`: каждая `revisionN_checks` сравнивает текущие файлы с хешами своей предрегистрации и
читает deviations-файлы всех более поздних ревизий. Главный `e2e_offline` использует `--foundation v1`
по умолчанию.

## Goals / Non-Goals

**Goals:**
- трасса попытки, которую процесс атакующего не может подделать;
- доказательство изоляции, не зависящее от проверяемой стороны и чувствительное к флагам bwrap;
- явный уровень притязания в манифесте каждого прогона;
- правки общего кода не ломают проверки закрытых ревизий, а регрессии поведения по-прежнему ловятся;
- `L*` для рекомендуемой основы v2r.

**Non-Goals:**
- живые запросы к модели (0);
- изоляция защищаемой стороны;
- замыкание `/nix/store`;
- blind-набор, уровни B/C;
- изменение серверных правил, оценщика, корпусов и lock.

## Decisions

1. **Брокер — автор записи, ребёнок — только `self_report`.** Отклонённая альтернатива — сверка каждого
   поля ребёнка с копией брокера (critique fix 1): при каждом новом поле её пришлось бы расширять.
   Брокер уже знает номер попытки (`started`), реплики (возврат `next_message`), ответы
   (`observation`) и итог (`SessionResult`). Ребёнок присылает
   `{"t":"record","self_report":{"tactics":[...],"believed_success":bool}}`. Длина `tactics` равна числу
   ходов брокера, иначе — нарушение. `believed_success` по-прежнему может остановить кампанию: прекратить
   атаку — право атакующего. Но в записи поле помечено как самоотчёт. Версия протокола IPC → 2.
2. **Ошибки разбора — нарушение протокола.** `_pump` и `finish_attempt` оборачивают обработку `event`
   и `record`. Исключения `IPCProtocolError`, `EventLogError`, `TypeError`, `KeyError`, `ValueError` ведут в
   `_ipc_violation`. Событие `attempt` от ребёнка допускается только с `cost=null`, и его `episode_id`
   равен открытой попытке.
3. **Пробы — код брокера.** Пробный модуль не входит в staged-пакет атакующего, монтируется ro отдельным
   путём и запускается той же командой `BwrapLauncher.argv`. Брокер дополнительно читает
   `/proc/<pid>/stat` (sid) и `/proc/<pid>/status` (NSpid) процесса атакующего. Для `--die-with-parent`
   брокер запускает пробный процесс через промежуточного родителя, убивает его SIGKILL и ждёт
   исчезновения ребёнка не дольше 5 с. По руководству bwrap (sources W1) `--cap-drop ALL` действует
   только при привилегированном запуске, поэтому MX3 допускается как эквивалентный мутант при
   документированном `CapEff=0`.
4. **`claim_level` — часть манифеста.** `build_manifest(..., claim=...)` пишет `claim_level` и факты.
   Без фабрики — `in_process_research`. `reproducibility_errors` требует поле для схемы
   `darp.run_manifest/2`; старые манифесты `/1` читаются как исторические. Живой A без bwrap требует
   флага `--in-process-research`.
5. **Исторические проверки.** Для закрытой ревизии N проверка состоит из:
   (а) sha256 предрегистрации N;
   (б) sha256 записанных при прогоне артефактов N (кассеты, сводки);
   (в) поведенческой проверки — replay кассет, пересчёта таблиц, мутантов N.
   Хеши текущего кода против замороженных выводятся в поле `drift` и FAIL не вызывают. Если у ревизии
   нет поведенческой проверки, её хеш-проверка остаётся FAIL-проверкой; такие ревизии перечисляются.
   Новые deviations-файлы для чужих ревизий не создаются.
6. **v2r — главная основа.** `e2e_offline` идёт с `--foundation v2r`, а прежний v1 становится шагом
   `e2e_legacy_v1`. Приёмка проверяет корректность статусов `L*` по формуле break-even §9.2, а не знак эффекта.

## Risks / Trade-offs

- [Историческая проверка ослабит защиту от регрессий] → поведенческие проверки и отрицательный
  контроль «мутант меняет исход rev7/rev8 → FAIL»; ревизии без поведенческой проверки сохраняют
  хеш-FAIL.
- [Запись брокера разойдётся с in-process] → обязательная побайтная регрессия D/A на заглушке. При
  расхождении задача не implemented.
- [Пробы зависят от хоста] → на хосте без userns — явная ошибка или `in_process_research`, а не PASS.
- [MX3 эквивалентен] → документировать выводом пробы, а не объявлять убитым.
- [Рост времени verify от v2r] → публикуется. Свыше +20 % legacy v1 сокращается до seed 7 с записью
  упрощения.
- [Ожидаемо нулевой эффект на v2r] → это допустимый результат. Гейт не зависит от знака.

## Migration Plan

1. `revision-scoped-checks` первым, с RED на правке комментария в `runner/flow.py` в копии.
2. `broker-authoritative-record` (IPC v2) с регрессией D/A.
3. `broker-side-isolation-evidence` с мутантами MX2/MX3/MX4/MX6.
4. `claim-level-in-manifest`: схема манифеста `/2`, матрица `enforcement`.
5. `v2r-primary-table`.
6. Быстрая команда `scripts/rev10_verify.py`, затем один полный verify из чистой копии.

Откат: снимок rev9 (candidate) сохраняется; `--foundation v1` остаётся доступным флагом.
Исторические артефакты не редактируются.
