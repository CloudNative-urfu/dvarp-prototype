## 1. Что построено

Исполняемый полигон на Python ≥ 3.11 только со стандартной библиотекой (`darp_range/`, ~20 пакетов).
Он сравнивает конфигурации гвардрейлов в одном бизнес-процессе — агент поддержки возвратов
интернет-магазина на синтетической SQLite-БД — и считает порог окупаемости `L*`.

Что есть в данных (офлайн, на заглушке модели; это проверка сквозного расчёта, а не вывод о
гвардрейлах): на seeds 7/8/9 Pareto-фронт — `{g_simple}`. `L*` g_in ≈ 6 USD (диапазон 3–15), g_in_oss
≈ 63 USD. g_out и «чистый детектор» не дают выигрыша в безопасности (`no_safety_gain`). На основе
boundary-2 заглушка не исполняет ни одного нарушения ни в одной из 72 ячеек диагностики, поэтому эффект
гвардрейлов сверх серверных правил на этой сетке не измерим.

## 2. Как запустить

```sh
# verify_command (submission.json) — из корня чистой копии; офлайн, без сети и модельных API, ~33 мин.
# Зависимостей нет (requirements.txt пуст), код 0 только если прошли все шаги.
python3 scripts/verify_e2e.py --out runs/verify

# то же в изоляции: netns без внешних интерфейсов, поднятый lo, вложенный userns, RESEARCH_LLM_* сняты
sh scripts/isolated_verify.sh runs/verify_isolated

# run_command (submission.json) — живой режим A через RESEARCH_LLM_BASE_URL / _MODEL (/ _API_KEY).
# Лимиты: ≤60 запросов, ≤150000 токенов, ≤900 с, ≤13 запросов на эпизод/ячейку; --out не должен существовать.
python3 scripts/live_mode_a_v.py --prereg artifacts/preregistration-rev5.json --out runs/live_A \
    --interleave --entries atk-06,atk-08 --cell-budget 13 --max-requests-per-episode 13 \
    --max-requests 60 --max-tokens 150000 --max-wall-s 900

# отдельные офлайн-прогоны
python3 -m darp_range.report_cli offline --out runs/v2 --foundation v2 --seeds 7
python3 -m unittest discover -s tests -t .
```

Без переменных `RESEARCH_LLM_*` команда `run_command` завершается с кодом 2 (`LLMConfigError`) и не
обращается к сети.

## 5. Упрощения и принятые допущения

Полный список — `artifacts/simplifications.json` (216 записей `{component, what, why, upgrade}`; та же
копия — в `status.json`). Допущения — `artifacts/decomposition.json → assumptions` (23 записи). Главные:

- **Модель офлайн** — правило-ориентированная заглушка за интерфейсом chat completions. Офлайн-таблицы
  характеризуют заглушку, а не реальную модель.
- **Правила возврата R1–R5 и цены** заданы допущением: C_refuse 5–40 USD, C_queue 0.10–1.00 USD/мин,
  C_manual 3–15 USD, токены 0.05–0.50 USD/1M. `L*` приводится на границах диапазонов.
- **Очередь** — симулированное время в минутах, пуассоновские прибытия по seed, обслуживание 4/8/15 мин.
  Это не измерение живого оператора.
- **Гвардрейлы** — встроенные детерминированные плагины как класс «дешёвый текстовый детектор /
  валидатор». Из OSS-каталога закреплён один детектор (deberta-pi-v2), выключен по умолчанию; остальные
  позиции каталога (NeMo, Llama Guard, Granite Guardian…) не подключены.
- **g_proc** — правила процесса без чтения смысла текста (дедупликация, квоты, порог суммы). **g_simple**
  — форма с закрытым списком причин и регулярные выражения.
- **Легальный клиент**: по умолчанию `facts` — пересказывает факты и никогда не подтверждает. Модель, ждущая
  «yes», не завершит обращение; это ограничение симулятора, оно закреплено тестом. `grammar_rev5` сохранён
  для воспроизведения rev5.
- **boundary-2**: законные исключения (evidence, одобрение оператора) берутся только из фикстуры эпизода,
  процесс оператора не моделируется. Гарантия конкурентности держится на сериализуемости SQLite.
- **Хранение**: сырые прогоны rev6 упакованы в `runs/archive/*.tar.xz` с SHA256SUMS; копии прогонов rev5
  заменены манифестами (ограничение размера снимка).
- **RED на поведении rev5** показан мутантами-возвратами в этом каталоге, а не на копии кода rev5.

## 6. Известные поломки и слабые места

- **Выводы о гвардрейлах на живой модели отсутствуют.** Все сравнительные таблицы — на заглушке. Живой A:
  n = 3 сценария, попытки частично обрезаны бюджетом ячейки (теперь честно `outcome=null`).
- **На boundary-2 эффект гвардрейлов не измерим на текущей сетке**: g0 уже даёт V = 0. Прежний вывод
  «g_simple доминирует» относится к процессу без серверных R1/R2/R5.
- **Живой легальный срез g0 на boundary-2 не выполнен.** `report_cli live` требует атаку в срезе. Вопрос
  «эскалирует ли модель после серверного отказа» открыт; на заглушке ответ «нет» (ctl-06 → `lost`).
- **Остаточные поверхности не измерены**: цели slow/burn/shift на живой модели, PII в тексте ответа,
  `orders.note` / история обращения как канал инъекции, выбор не того допустимого действия. Привязка
  возврата к заказу обращения не является инвариантом ни на одной границе.
- **NFR-2.3 на живой модели**: у внешнего провайдера повтор при temperature 0 расходится; это фиксируется
  как дефект, а не устраняется.
- **ProcessGate / g_simple / evaluator-1 считают повтор возврата без окна**, boundary-2 — в окне 30 дней.
  Расхождение записано в карте отличий `BOUNDARY_V1_TO_V2` (`darp_range/executor/boundary.py`), но не
  устранено.
- **run_command без переменных окружения** падает с трассировкой (`LLMConfigError`, код 2) и успевает
  создать пустой каталог `--out`. Повторный запуск с тем же `--out` потребует удалить его вручную.
- **Журналы критика rev5** (пробы, живой прогон) в рабочем каталоге отсутствуют; пробы восстановлены по
  таблице.
- **Статья (NFR-2.14 п. 5) не написана** — вне zero-версии по brief.
