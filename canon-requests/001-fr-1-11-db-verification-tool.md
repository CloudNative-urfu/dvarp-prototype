# 001. FR-1.11 — тул проверки/уточнений по внутренней БД

- **Дата:** 2026-11-15
- **Источник:** dvarp-prototype#39 (тула агента), требование тимлида 2026-11-15
- **Статус:** open

## Что сделано в прототипе

- БД сервиса возврата доведена до схемы v3 (`darp_range/state_store/migrate_v3.py`,
  PR #43): аудит очереди операторов, жизненный цикл заявки, индексы; дизайн —
  `docs/refund-db-design.md` (§2, §3, §8).
- Требование: агенту нужен доступ к **внутренней БД прогонов** для уточнений и
  проверки реальности возврата — покупал ли клиент раньше, история заказов и
  возвратов, существование заказа (сейчас `read_order` отдаёт только один заказ
  по id: `darp_range/tools/specs.py:57`, `darp_range/executor/executor.py:315`).
- Текущий набор тулов закрыт каноном и кодом: ровно 5 инструментов
  (`darp_range/tools/specs.py:131` — `assert len(TOOL_SPECS) == 5`).

## Какой канон устаревает

- `dvarp` `docs/guardrails_requirements.md`, **FR-1.11 «Набор инструментов»**:
  «ограниченным набором из 5 инструментов» — не покрывает проверку истории
  покупок/реальности возврата по внутренней БД.
- Следствие: замороженный (после финализации) набор `tools/`/`executor/` не
  сможет содержать новый инструмент без отклонения от канона.

## Предлагаемая правка

Два варианта (выбор — за владельцем; в #39 фиксируется выбранный):

1. **Новый 6-й инструмент** (например, `check_purchase_history` /
   `verify_refund_claim`): доступ только к данным текущего клиента
   (`WHERE customer_id = …`), без ролей/PII (FR-1.3, NFR-2.13). Правка FR-1.11:
   «из 6 инструментов» + описание пункта; запись в «Отклонения канона»
   (дата, причина, issue).
2. **Расширение `read_order`** (без изменения числа тулов): выдача истории
   заказов/возвратов клиента и проверки существования заказа в рамках
   существующего инструмента; FR-1.11 формально не меняется, но требуется
   запись в «Отклонения канона» о расширении семантики.

## Влияние

- `dvarp-prototype#39` (тула агента) и последующая заморозка `tools/`/
  `executor/` — состав инструментов фиксируется каноном.
- Документы канона: `docs/guardrails_requirements.md` (FR-1.11, «Отклонения
  канона»); при варианте 1 — также `docs/guardrails-research-design.md`
  (описание инструментов, если есть).
- До принятия заявки в #39 допускается реализация поверх текущего набора
  (чтение в рамках `read_order`), без правки канона.
