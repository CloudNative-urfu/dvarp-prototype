# 004. Контракт СС↔полигон: привязка §11 к реализации

- **Дата:** 2026-11-18
- **Источник:** #19 (PR #55 — svc-decomposition, контракт traffic-svc), #33 (PR #56 — metrics-svc), будущая #36 (traffic-svc)
- **Статус:** open

## Что сделано в прототипе

Канонный контракт СС↔полигон (принципы) получил конкретную реализуемую форму:

- приглашение потока и порты трафика — `darp_range/runner/ports.py:85`
  (`FlowInvite`: конфигурация, seed, бюджет, id + хеш снимка БД), `:118-123`
  (`TrafficPort.schedule`/`bind`: расписание легальных прибытий → привязанные
  к реальным строкам БД эпизоды);
- контракт traffic-svc (текст-only наружу, внутренности — задача #36) —
  `openspec/changes/svc-decomposition/specs/traffic-service/spec.md`;
- HTTP-протоколы поверх `svckit` (`darp_range/svckit/http.py`: ready.json,
  JSONL-лог запросов; отказ по дрейфу заморозки → exit 3 → ячейка `refused`):
  defender-svc — `defender_svc/server.py`, metrics-svc —
  `darp_range/metrics_svc/server.py:98` (`POST /runs`, `/runs/<id>/results`,
  `/runs/<id>/log`, `/runs/<id>/finish`);
- целостность телеметрии — `metrics_svc/server.py:146`: разрыв персобытийной
  хеш-цепочки → `422 telemetry_invalid`; движок отказывается считать
  разорванную цепочку;
- барьер атакующего — архитектурные импорт-тесты (`tests/test_defender_svc.py`,
  static + live `/health`).

## Какой канон устаревает

`dvarp` `docs/kb/guardrails-research-design.md`, §11 «Контракт СС↔полигон»
(срез ~L244-252): принципы верны, но

1. целостность телеметрии не зафиксирована (передача «рядом с ответом» без
   условия верифицируемости);
2. не описана сторона СС по легальному трафику: кто отдаёт расписание
   легальных прибытий и принимает привязанные эпизоды, гарантия того, что
   состояние процесса не покидает СС;
3. нет указания, где живёт конкретная спека контракта (порты, протоколы) —
   канон фиксирует инварианты, реализация — в спеках прототипа.

## Предлагаемая правка

Дополнить §11 «Контракт СС↔полигон» тремя пунктами:

> - Телеметрия передаётся с проверкой целостности: персобытийная хеш-цепочка;
>   движок метрик отказывается считать разорванную цепочку (условие валидности
>   прибора, а не политика).
> - Легальный трафик в СС: СС предоставляет полигону детерминированное от seed
>   расписание легальных прибытий и принимает привязанные к состоянию эпизоды;
>   состояние процесса не покидает СС, наружу — только текст диалога и
>   телеметрия.
> - Конкретные API контракта (порты, HTTP-протоколы) живут в спеках прототипа
>   (openspec `svc-decomposition`; `docs/manuals` — образец для полигона);
>   канон фиксирует границы и инварианты, не сигнатуры.

Противоречий с текущим §11 нет — сужение принципов до проверяемых инвариантов.

## Влияние

- #36 (traffic-svc) реализует легальный трафик как сервис по этому контракту;
- перенос движка метрик на полигон (проект другой части команды) — по тем же
  пунктам (цепочка целостности + граница текста);
- барьер атакующего в §11 уже зафиксирован — не меняется.
